方案建设背景

📋 业务背景与智能体感知诉求

集团数据蓝图与风控预警能力建设要求，持续加强对区域、市场、客户相关公开信息的监测与早预警。当前风险与舆情线索广泛分布在政府及行业网站、抖音 / B 站等视频平台、微信公众号 / 微博等自媒体中，信息来源多、更新快、结构不统一，人工跟踪与脚本维护成本高。例如：一是网站公开信息（政策、处罚、经营异常等）可提前反映客户或区域风险；二是短视频与直播场景中的黑产导流、违规宣传等线索传播快、易发酵；三是公众号与微博等文字内容常成为舆情扩散的第一现场；四是现有采集仍依赖人工维护 RPA / 爬虫脚本，目标增减与页面改版后难以及时扩展。因此，有必要建设风险舆情监控平台（亦可作为统一信息订阅能力独立运行），以 AI 自动编写采集 / RPA 脚本、动态任务下发与结构化回传为核心，为总部风险分析等业务方提供可配置的全网检索数据源。

平台定位：解决什么问题

🎯 项目定位与目标

风险舆情监控平台是风控情报能力的数据底座与统一订阅入口。 它将传统零散的、一次性的人工检索与手写脚本，升级为可配置、可追踪、可自愈的智能采集与订阅引擎。 平台覆盖网站公开信息、视频平台（抖音 / 视频号 / B 站等）与公众号 / 微博等文字渠道，通过大模型自动生成并验证采集 / RPA 脚本，将配置动态下发至外网执行单元，持续抓取后统一为结构化数据，经公司 API 回传下游系统。

核心价值：通过「自动化找源 → AI 写脚本 / RPA → 验证 → 定时复用与自愈 → 结构化回传」闭环，为总部风险分析等业务方提供标准化原始数据表，支撑全网检索与后续模型研判。

⚠️ 核心解决的痛点

  • 信息渠道分散：网站、视频、公众号 / 微博各自为政，难以形成统一情报视角与标准数据表。
  • 脚本人工维护成本高：RPA / 爬虫依赖人工编写，目标增减与页面改版后扩展慢、失败后难自愈。
  • 业务自助订阅不足：风控与分析部门难以及时按关键字 / 提示词配置全网检索，数据回传链路不统一。
2

解决方案：AI找源写码自愈

本方案以 AI 贯穿找源—写脚本（含 RPA）—验证—自愈，降低人工运维成本，并将多通道采集结果经公司 API 回传，形成可订阅的情报数据闭环。

🤖

AI 找源与写脚本

平台可由 AI 联网发现网站数据源并生成爬虫脚本；视频 / 公众号等由管理员指定目标后 AI 生成 RPA 脚本。经验证（网站可走隔离环境，RPA 须真机试跑）后入库复用，新增目标时无需人工手写。

🔁

失败自愈，少靠人盯

访问被拒时自动切换代理 IP；页面改版或元素定位失败时回流 AI 诊断并重写脚本再验证，把「改版 / 封禁」从人工运维转为自动修复。

🔗

与公司 API 闭环协同

内网完成订阅与任务配置，外网执行采集后按统一字段结构化回传公司 API，供总部模型研判或下游系统订阅消费。

三条独立流程

① 网站：AI 检索 → 渠道增强 → 写爬虫 → 验证（隔离环境） → 代理 IP → HTTP 抓取。
② 视频 RPA：手动指定博主/词 → 写 RPA → 验证（真机） → 下发手机 → App/OCR。
③ 自媒体 RPA：手动指定公号/话题 → 写 RPA → 验证（真机） → 下发手机 → App/OCR。
① 突出 AI 找源 / 渠道增强；②③ 突出 AI 写 RPA。代理 IP 仅属于网站链路。

协同与自愈要点

  • 验证语义：统称「验证」——网站可用隔离环境；RPA 必须真机试跑，避免「沙箱」歧义。
  • 网站自愈：拒访换代理 IP；改版失败回流 AI 重写爬虫。
  • RPA 自愈：账号异常换机/号；元素失效回流 AI 重写 RPA。
  • 数据回传：三流程汇合为统一字段，经 JSON 推入公司 API。

核心技术：一次生成，持续复用

当确定一个新的数据源（如政府网站 RSS、抖音关键词任务、固定公众号列表）后，AI 模型自动编写对应的 Python 爬虫或手机端 RPA 脚本，并立即验证：网站脚本可在隔离环境执行，RPA 脚本须在真机试跑，确保能成功抓取结构化数据并落库。验证通过后脚本进入脚本库，后续每日定时任务直接复用该脚本，不再调用大模型，Token 消耗从「每次交互」降低为「一次生成」。

若某脚本连续执行失败 2–3 次（如目标 App 改版、元素定位失败），系统自动触发 AI 诊断并重写脚本再验证，实现自我修复，保证多通道采集持续可用。

完整业务闭环

  • 数据采集：引擎按执行单元并行调度，覆盖网站爬虫与视频 / 公众号 RPA 任务。
  • 数据落库：统一为标题、描述、来源平台、发布时间、链接等标准字段写入 PostgreSQL。
  • 匹配与聚合：按订阅主题、关键字 / 提示词从库中匹配相关信息并去重聚合。
  • 信息回传：经公司 API 将标准数据表推送给总部风险分析等下游；亦可按规则邮件 / 告警分发。

数据源分层方案：确保信息准确与时效

🏛️

第一层：权威事实层

源库 ·官方 / 白名单站点

覆盖政府网站、监管通报、行业协会等权威公开渠道，由管理员维护白名单并配置定时采集。 该层产出用于确认事件是否属实、补齐发生时间与责任主体，作为风险评估中的「硬事实」依据；可信度最高，优先写入结构化情报，不依赖社媒传闻。

📡

第二层：全网增量发现层

源库 ·视频 · 公号 · AI 检索

网站通道可按关键字 / 提示词由 AI 联网检索扩源；视频与公众号 / 微博等 RPA 通道以管理员手动指定博主、关键词、账号列表为主（不走 AI 找源与渠道增强）。 确认目标后触发 AI 生成 / 验证对应脚本并入库复用；与权威层交叉印证后进入订阅匹配与 API 回传。

谁在用：系统角色与使用边界

⚙️

系统管理员

范围 ·平台全局运维

负责设定订阅主题与多通道采集任务（网站 / 视频 / 公众号），管理执行单元（手机等）与 AI 发现源确认，配置公司 API 回传鉴权，监控脚本 / RPA 健康度与引擎状态。

📊

总部风险分析

范围 ·标准化原始数据（优先用户）

按关键字 / 提示词自助订阅全网检索结果，直接拉取标准数据表做模型研判与舆情趋势分析，平台侧重「数据源」角色，不强行提供解读结论。

🏢

机构风控 / 专项团队

范围 ·本机构 / 专项订阅

订阅本机构关注的风险主题或黑产关键词，接收定向回传 / 邮件摘要；可按需叠加告警等增值消费，与总部原始表能力形成分层。

系统三阶段建议演进路径

PHASE 1 · MVP 验证期

采集底座与多通道闭环

  • 打通网站 + 视频 RPA + 公众号 RPA 三类通道的基础配置与执行单元调度。
  • 跑通「AI 找源 → 脚本 / RPA 生成 → 验证 → 定时复用」全托管模式。
  • 固化标准字段回传公司 API，优先服务总部风险分析取数。
PHASE 2 · 深度运营期

源库沉淀与自助订阅

  • 沉淀权威站点白名单与视频 / 公号监控目标库，支持动态增减与任务下发。
  • 支持业务方按关键字 / 提示词自助订阅，完善失败自愈与执行单元健康度。
PHASE 3 · 智能策略联动

从数据流走向风控因子

  • 将多通道情报沉淀为可量化的风险信号与候选因子，供模型验证。
  • 与公司内部风控 / 告警体系对接，按消费方分层提供原始表或增值服务。
  • 实现「发现线索 → 校验因子 → 调整策略」的最终闭环。
