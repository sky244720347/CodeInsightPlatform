方案建设背景

📋 业务背景与智能体感知诉求

随着产业金融、产业研究、区域经济研判及重点客户管理需求不断提升，产业动态信息对业务决策和风险管理的影响越来越明显。当前，产业相关信息广泛分布在政府网站、行业协会、主流媒体以及第三方舆情平台中，信息来源多、更新快、结构不统一，人工跟踪存在较高成本。例如，一是政策变化可能直接影响某一产业的发展方向；二是安全事故、环保处罚、停工停产等事件可能提前反映企业或区域产业风险；三是行业景气度变化、项目扩产、产业链波动等信息可能对客户经营状态产生间接影响；四是短视频、公众号等新媒体信息往往具有传播速度快、发酵不确定性强的特点，容易形成突发舆情。目前，公司已具备一定数据采集和智能分析基础，但各类信息尚未形成统一的产业情报视角，也尚未与星云平台现有风控策略能力形成有效协同。因此，有必要在星云平台基础上建设产业情报智能体，作为产业动态感知和产业风险识别的前置能力。

平台定位：解决什么问题

🎯 项目定位与目标

星云棱镜产业信息订阅引擎是整个"产业情报智能体"的数据底座与订阅入口。 它将传统零散的、一次性的人工网络检索，升级为可配置、可追踪、可沉淀的智能订阅引擎。 平台通过大模型自主发现优质数据源，沙箱自动生成并验证采集脚本，持续抓取数据流并匹配产业风险语义，最终围绕监控主体形成结构化事件和分析报告。

核心价值：通过"自动化找源-沙箱脚本生成-定时去重监控-大模型分析报告"的闭环，为后续星云平台风险因子的沉淀与风控策略的发布提供长效 of 工程底座。

⚠️ 核心解决的痛点

  • 信息渠道分散：产业数据广泛分布于政府官网、行业协会、主流媒体与社交舆情，难以集中感知。
  • 手工跟踪成本高：业务部门缺乏自动化抓取逻辑与工具，每日人工筛选效率低、搜集负担重。
  • 决策获取不及时：管理层难以及时掌握产业的宏观与微观异常动态，容易导致风控策略调整滞后。

解决方案：AI找源写码自愈

本方案以 AI 贯穿找源—写脚本—验证—自愈，降低人工运维成本，并与星云平台形成可订阅的产业情报闭环。

🤖

AI 找源与写脚本

订阅平台可由 AI 联网检索发现数据源，并自动生成 Python 爬虫脚本，经沙箱验证后入库复用，扩展新源成本显著下降。

🔁

失败自愈，少靠人盯

访问被拒时自动切换代理 IP；脚本失败则回流 AI 重写并再验证，把「改版/封禁」从人工运维转为自动修复。

🔗

与星云闭环协同

星云下发配置、订阅平台推送数据，AI 采集结果直接进入结构化与邮件早报，形成可订阅的产业情报闭环。

整体架构

订阅平台以外网 AI 采集为核心：自动找源、生成并验证爬虫脚本、代理调度与失败自愈；星云平台负责配置下发与结构化推送。两侧通过「配置下发 / 数据推送」闭环协同，将产业情报持续沉淀为可订阅的邮件早报。

核心数据流

左 · 订阅平台：配置（配置同步接收星云下发；无邮件规则、无产业配置）→ 采集引擎（开始 → 脚本生成 → 沙箱 → 代理IP → 调度 → 获取 → 结束）→ 存储；采集结果推送至星云引擎。
右 · 星云平台：配置（含邮件规则、无爬取任务，并下发至订阅平台）→ 推送引擎（定时触发 → 订阅匹配 → 邮件发送）→ 存储读写。

协同与部署要点

  • 配置下发：星云侧页面配置同步到订阅平台配置层。
  • 数据推送：订阅平台采集结束后，将产业爬虫数据推入星云引擎做结构化与邮件。
  • IP / 脚本自愈：访问被拒换 IP 重试；数据获取失败回流 AI 脚本生成。

核心技术：一次生成，持续复用

当确定一个新的数据源（如「国家统计局 — 最新发布 RSS」）后，AI 模型自动编写 Python 爬虫脚本，并在隔离沙箱中立即执行验证，确保能成功抓取结构化数据并落库。验证通过后脚本进入脚本库，后续每日定时任务直接复用该脚本，不再调用大模型，Token 消耗从「每次交互」降低为「一次生成」。

若某脚本连续执行失败 2–3 次（如目标网站改版），系统自动触发 AI 重写脚本并重新验证，实现自我修复，保证数据抓取持续可用。

完整业务闭环

  • 数据采集：引擎每日定时并行执行所有爬虫脚本，抓取指定产业的昨日新闻。
  • 数据落库：抓取到的结构化信息（标题、摘要、来源、发布时间等）存入 PostgreSQL。
  • 匹配与聚合：按各机构/用户订阅的产业和关键字，从库中匹配相关信息并去重聚合。
  • 信息推送：将匹配结果聚合后，通过邮件发送给订阅用户，呈现产业、事件摘要、来源链接及利好/利差分析。

数据源分层方案：确保信息准确与时效

🏛️

第一层：权威事实层

源库 ·官方白名单

覆盖国家统计局、工信部、能源局、应急管理部及重点行业协会等官方站点与 RSS/通报渠道，由管理员维护白名单并配置定时采集。 该层产出用于确认事件是否属实、补齐发生时间与责任主体，作为风险评估与邮件早报中的「硬事实」依据；可信度最高，优先写入结构化情报，不依赖社媒传闻。

🔍

第二层：增量发现层

源库 ·AI 联网检索

按「产业 + 地区 + 风险词」自动组装检索意图，由 AI 联网 API 定时扫描尚未纳入监控的政策变动、安全事故、停工停产等突发线索。 发现候选源后推送管理员确认，再触发 AI 生成/验证爬虫脚本并入库复用；该层负责「扩覆盖、提时效」，与权威层交叉印证后，才进入订阅匹配与邮件推送。

谁在用：系统角色与使用边界

⚙️

系统管理员

范围 ·平台全局运维

负责设定要监测的产业（煤炭、纺织、水产等），配置爬取任务（频率、目标网站列表），管理 AI 发现的数据源确认流程，设定邮件发送规则，监控脚本执行健康度与引擎运行状态。

🏢

机构风控

范围 ·本机构产业订阅

订阅本机构关注的产业（如山西机构关注「煤炭」「山西煤矿爆炸」），配置自定义关键字，接收并解读定向推送的产业早报邮件，据此调整本机构授信与审批策略。

🏛️

总部风控

范围 ·全局跨产业情报

从集团视角订阅全局性、跨产业的关键信息（政策变化、行业暴雷、重大安全事故等），为宏观风控决策提供支持，统筹各机构产业风险态势。

系统三阶段建议演进路径

PHASE 1 · MVP 验证期

情报底座与采集闭环

  • 内置 5 个试点产业（煤炭、纺织、水产等）基础配置。
  • 跑通「AI 找源 → 脚本生成 → 验证 → 定时复用」全托管模式。
  • 实现邮件早报推送基本流程。
PHASE 2 · 深度运营期

情报沉淀与优化

  • 沉淀官方权威白名单源库（统计局、能源局、行业协会 RSS）。
  • 支持机构/总部风控自定义关键字与定向推送规则。
PHASE 3 · 智能策略联动

从情报流走向风控因子

  • 将定性的产业情报、利好/利差标签转化为定量行业健康度指数。
  • 构建候选风险因子，接入星云平台量化策略验证框架。
  • 实现「发现情报 → 校验因子 → 调整授信策略」的最终闭环。
